# 멀티플레이용 결정론 기반

2026-09-30 · 전투 규칙 19 · 편대 상태 형식 1

편대전의 계산·입력·저장 경로에 결정론 보강을 적용했다. 같은 규칙, 시작 시드, 틱별 입력으로 전투를 재현하고 중간 상태에서 이어 계산할 수 있다. 현재 조작 가능한 플레이어는 한 편대이며, 나머지는 기존 AI다. 10~30명의 실제 접속, 방 관리, 여러 플레이어의 입력 배분, 소켓 통신은 이 변경에 포함하지 않는다.

## 적용 내용

- `deterministic-math.mjs`: 시뮬레이션의 삼각함수·제곱근·지수·비정수 거듭제곱을 공통 산술로 계산한다. 전역 `Math`와 화면 표시 계산은 바꾸지 않는다. 삼각함수 입력은 절댓값 1e9 이하를 지원하며, 정확도 목표는 게임에서 사용하는 범위다.
- `simulation-rng.mjs`: 기존 LCG 수열을 유지하고 현재 난수 상태 복원을 지원한다. 파티클 난수는 별도 흐름을 사용한다.
- `engine.mjs`, `fleet-battle.mjs`: 드론의 고유 ID, 일관된 배열·동률 처리 순서, 이전 틱의 드리프트 읽기를 적용했다. 편대전은 60Hz 고정 틱을 사용한다. 명시적 시드는 전장 초기화 전에 적용된다.
- `fleet-state.mjs`: 위치뿐 아니라 AI 제어, 회전·드리프트·합류 상태, 특성, 생성 타이머, 난수 상태와 ID 할당기까지 저장·복원·지문 계산에 함께 사용한다. 렌더링·공간 검색 캐시는 제외하고 복원 시 다시 만든다. 스키마에 없는 새 필드는 누락시키지 않고 오류로 알린다.
- `fleet-session.mjs`, `replay.mjs`, `app.mjs`: 실제 플레이가 같은 입력 실행 경로를 사용한다. 중복·건너뛴 틱과 잘못된 입력을 거부하고, 완료된 편대전은 최신 한 건을 로컬에 저장한다. 기존 재생 메뉴나 순위 업로드는 추가하지 않았다.

## 공통 실행 경로

```js
import { FleetBattleGame } from '../src/fleet-battle.mjs';
import { FleetSession } from '../src/fleet-session.mjs';

const session = new FleetSession(new FleetBattleGame(), {
  seed: 12345,
  record: false, // 서버에서 전체 입력 기록이 필요 없을 때
});
session.step(session.tick, { targetX: 500, targetY: -200, boost: true });
const checkpoint = session.checkpoint();

const copy = FleetSession.restore(
  new FleetBattleGame(),
  JSON.parse(JSON.stringify(checkpoint)),
);
copy.catchUp([
  { tick: checkpoint.tick, input: { targetX: 500, targetY: -200 } },
]);
```

`tick`은 실행 전까지 완료한 틱 수다. 새 게임은 0번 입력을 받아 1틱 상태가 된다. 체크포인트의 다음 입력도 그 체크포인트의 `tick` 번호부터 시작한다. 멈춤·종료 상태에는 입력을 진행시키지 않는다. 중간 체크포인트로 복원한 세션은 빠진 입력 기록이 없으므로 처음부터의 완전한 재생 파일을 만들어 냈다고 취급하지 않는다.

상태 형식은 편대전 전용이다. JSON 왕복에서 음의 0과 무한대도 유지하며, 좌표를 반올림하지 않는다. 진단용 32비트 지문이 같다는 사실만으로 상태 동일성을 증명하지는 않는다. `firstFleetDifference`와 전체 직렬화 결과로 차이가 난 필드를 확인할 수 있다. 복원 데이터의 버전·필수 필드·ID·참조를 먼저 검사하므로 잘못된 체크포인트는 현재 게임을 바꾸지 않는다.

체크포인트 한 건의 제한은 지휘기 256대, 드론 총 20,000기다. 현재 JSON 형식은 초기 접속·복구·진단을 위한 것으로, 매 틱 전체 상태를 전송하는 용도가 아니다. 향후 방 서버는 입력 순서를 확정하고 동일한 시뮬레이션을 실행하며, 전체 상태는 초기 동기화나 불일치 복구 때 사용할 수 있다. 결정론은 드론 상태의 상시 전송을 줄이는 기반이며, 서버의 전투 계산 자체를 없애지는 않는다.

## 검증

- 전체 자동 테스트 **369개 통과**, 실패 0. 시드와 복원 난수 상태의 `-0`도 unsigned 32비트의 `0`으로 정규화한다.
- 배포용 빌드 성공. 생성된 서버 묶음을 실제로 불러와 `fetch` 진입점도 확인했다.
- Node 24.21.0, Chromium 145.0.7632.6, macOS 26.6 JavaScriptCore에서 같은 소스 묶음과 입력으로 비교했다. 초기 드론 4·32·128기의 세 장면을 각각 1,800틱 진행했다. 초기 및 120틱 간격의 **48개 전체 상태 비교 지점**이 세 환경에서 정확히 일치했다. 32·128기 장면은 전투 종료 없이 긴 계산을 확인하기 위해 지휘기에 무적 상태를 사용했다.
- 비교한 전체 결과는 환경당 4,330,035바이트이며 SHA-256은 `d9783ff7ac82f89c4478ad75a94c2da863526da2b9300e6c5be830d0504785bd`로 같았다. Node의 원본 모듈 실행과 비교용 묶음 실행도 일치했다. JavaScriptCore는 시스템 프레임워크를 직접 실행했으며 Safari 브라우저 전체 검사는 아니다.
- 중간 저장·복원, 소속 변경 대기 참조, 배열 반전, 아주 작은 수치 차이, 시각 효과 분리, 잘못된 입력·체크포인트, 실제 종료까지의 재생을 검사했다.
- 임시 Chromium의 실제 앱에서 시작·일시정지·재개·종료 화면을 확인했다. 시드 21981의 전투가 861틱에 종료되어 로컬에 저장됐고, 저장본을 재생한 전체 상태 지문이 일치했다. 브라우저 실행 오류는 없었다.
- 예전 재생 샘플은 새 규칙으로 실제 전투를 다시 계산해 갱신했다. 성장 획득 1회, 최대 8기, 시설 파괴 1회, 전사라는 기존 검증 조건을 유지한다. 규칙 18의 기록은 새 규칙에서 재생하지 않는다.

### 계산 비용 측정

이 Mac의 Node에서 같은 조건으로 120틱을 준비한 뒤 300틱을 측정했다. 지휘기는 무적이고 중립 드론 공급·추가 적 생성은 중지했다. 따라서 충돌·치열한 합류·네트워크·렌더링을 포함한 실제 서버 수용량 측정은 아니다.

| 지휘기 / 드론 | 변경 전 평균 | 변경 후 평균 | 변경 후 95백분위 |
| --- | ---: | ---: | ---: |
| 10대 / 총 160기 | 0.48ms | 0.62ms | 0.72ms |
| 30대 / 총 960기 | 3.36ms | 4.63ms | 4.98ms |
| 30대 / 총 1,920기 | 7.89ms | 11.58ms | 12.63ms |

다른 기기·엔진 버전까지의 보장은 별도 회귀 검증이 필요하다. 방 서버를 연결할 때에는 실제 전투 밀도, 여러 방의 동시 실행과 통신 부하를 포함해 다시 측정한다.
