# 대형 편대 성능 확인 — 2026-09-30

## 원인

실제 서울 서버에서 AI 한 편대가 드론 430기를 보유한 전장을 캡처했다. 전체 드론은 696기(회색 드론 231기 포함)였다. 10초 동안 받은 시뮬레이션 프레임은 156개였고 입력 프레임의 JSON 크기는 약 12 KB였다. 이 측정에서는 대역폭보다 시뮬레이션 계산이 병목이었다.

서버는 60 Hz로 전장 전체를 계산하고 입력 프레임을 보낸다. 브라우저도 같은 전장을 계산한다. 전체 위치 정보는 입장·퇴장·재동기화 스냅샷에 포함되고, 일반 프레임마다 모든 드론 위치를 보내지는 않는다. 화면 밖의 드론도 다른 편대에 영향을 주므로 계산에서 제거할 수 없다.

## 변경

- 공간 격자의 조회에서 문자열 키 생성 대신 숫자 행·열 조회를 사용한다. 후보 방문 순서는 유지한다.
- 적 편대의 영향 범위와 겹치지 않으면 영향력 검사를 건너뛴다.
- 정지한 회색 드론은 합류·유예 시간 계산만 수행하고 불필요한 이웃 비행 계산을 생략한다.
- 분리 힘, 상류 이웃, 최근접 7기 선택 어디에도 영향을 줄 수 없는 후보는 비싼 거리 계산 전에 제외한다. 근접 경계와 동률은 기존 계산을 사용한다.
- 클라이언트가 패킷을 기다린 시간을 누적해, 다음 3틱을 한 번에 처리하던 현상을 수정한다. 실제 밀린 프레임의 제한된 따라잡기는 유지한다.

편대 상한, 성장, 이동·충돌 규칙과 난수 순서는 바꾸지 않았다.

## 검증

- 같은 실제 전장 복사본의 300틱 계산: 로컬 Node.js 24에서 평균 22.40 ms → 8.44 ms/틱. 약 62% 감소, 약 2.65배 처리 속도. 서버나 모든 기기의 FPS 보장 수치가 아니다.
- 수정 전후 같은 전장을 2,400틱 실행해 120틱마다 비교한 정확한 상태 지문 20개가 모두 일치했다.
- 전체 자동 테스트 413개 통과. 격자 방문 순서·경계·동률, 회색 드론 합류, 패킷 대기 후 프레임 진행 검사를 포함한다.
- 실제 SDK 두 연결에서 430기 이상 AI 편대의 상태 지문이 일치했다. 두 복제 시뮬레이션을 같은 Node 프로세스에서 실행하면 검사기 자체도 CPU를 사용하므로 이 결과를 서로 다른 기기의 FPS로 해석하지 않는다.
- 별도 단일 클라이언트 검사에서 최대 편대 491기, 전체 791기 상태를 10초 동안 평균 59.8틱/초로 진행했고 상태 지문 10개가 일치했다. 이는 로컬 테스트 서버 측정이다.

극단적으로 밀집시킨 추가 검사에서는 860기 편대가 약 31 ms/틱, 1,290기가 약 60 ms/틱이었다. 무제한 성장 규칙은 유지했지만 처리 가능한 개체 수가 무한한 것은 아니다. 이후에도 대형 편대에서 문제가 남으면 이 전장 크기를 기준으로 추가 최적화해야 한다. 접속자 수만 늘리는 검사는 장시간 성장에 따른 성능을 검증하지 못한다.
