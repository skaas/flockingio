# 단일 방의 인원과 AI 운영 규칙

2026-09-30 · 공개 방 한 개 · 목표 동시 접속 10~30명

## 확정된 게임 규칙

- 전장에는 사람과 내부 AI를 합쳐 살아 있는 지휘기 편대를 최소 5개 유지한다. 회색 중립 드론과 사망 후 결과 화면을 보고 있는 사람은 이 수에 포함하지 않는다.
- 사람이 한 명도 없어도 AI 전투를 계속 진행한다. 사람이 없어지면 시뮬레이션을 정지한다는 이전 제안은 사용하지 않는다.
- 신규 입장, 사망 후 재출격, 접속이 끊긴 뒤 다시 입장하는 경우 모두 드론 4기로 새로 출격한다.
- 나가기와 접속 끊김은 같은 규칙을 적용한다. 남아 있는 편대의 지휘기·드론 ID, 위치, 속도, 에너지, 생존 상태를 유지하고 조작 주체만 내부 AI로 전환한다. 인간의 마지막 조작 입력은 버린다.
- 재접속 조작권 회수, 이전 편대 예약, 성장 복구는 제공하지 않는다. 이전 편대가 살아 있어도 돌아온 사람은 새 편대로 시작한다.
- 한 편대가 격추되어도 방의 전투는 계속한다. 빈자리를 AI로 채워 틱 처리가 끝날 때 최소 5개 편대를 유지한다.
- 자동 보충 AI가 있는 경우 신규 사람을 받으면서 보충 AI를 교체할 수 있다. 떠난 사람의 AI 편대는 여유가 있는 동안 유지한다.
- 한 방의 살아 있는 편대와 접속자 정원은 각각 30이다. 살아 있는 편대가 정원에 도달하면 조작 중인 사람을 보존하고 AI 자리를 새 출격에 사용할 수 있다. 사람 정원이 가득 차면 입장을 거부하고 안내한다. 두 번째 방은 만들지 않는다.
- AI 인계는 기존 게임 AI를 사용하며 외부 생성형 AI 서비스를 호출하지 않는다.

## 구현 경계

`src/fleet-room-game.mjs`에 여러 편대의 입력과 내부 AI를 함께 계산하는 방 시뮬레이션을, `src/fleet-room.mjs`에 입장·퇴장·새 출격·최소 인원 보충 규칙을 구현했다. `server/fleet-room.mjs`는 기존 import를 위한 재내보내기다. 기존 단독 플레이 엔진과 분리했으며 기존 기록의 규칙 버전 19는 유지한다.

방 운영 코드는 접속별 입력을 검사하고 순서가 지난 입력을 거부한다. 각 틱에 살아 있는 연결 편대는 입력이 아직 도착하지 않았어도 중립 조작을 받고, 연결이 제거된 편대는 내부 AI를 사용한다. AI와 사람이 같은 기체 물리 규칙을 사용하므로 조작 주체 전환으로 속도·기체 크기·에너지·무적 시간이 초기화되지 않는다.

`checkpoint()`는 서버 복구용이며 접속별 조작 정보도 포함한다. 클라이언트에 그대로 노출하는 공개 메시지가 아니다. 공개 목록에는 접속 식별자를 넣지 않는다. 방 저장·복원은 서버 상태 보존 기능이며, 떠난 사람에게 과거 편대를 돌려주는 기능과는 별개다.

`server/colyseus-room.mjs`가 Colyseus 접속·퇴장 이벤트를 방 운영 코드에 연결하며, 서버가 발급한 접속별 식별자로만 입력을 전달한다. 닉네임이나 재사용한 계정 ID를 조작 권한으로 사용하지 않는다. 이전 소켓에서 늦게 도착한 입력·퇴장 이벤트가 새 접속에 영향을 주지 않도록 새 연결은 새 접속 식별자를 사용한다. 끊김 감지는 통신 heartbeat가 담당한다. SDK의 자동 재접속과 Colyseus의 이전 편대 예약 경로는 사용하지 않는다.

`src/fleet-room-protocol.mjs`와 `src/fleet-network.mjs`가 서버가 확정한 입력을 전달하고 같은 시뮬레이션을 재현한다. 평상시에는 입력을 묶어서 보내고, 입장·퇴장·재출격·동기화 복구 시 공개 스냅샷을 보낸다. 공개 데이터에는 접속 식별자와 서버 입력 권한이 포함되지 않는다. 상태 확인용 지문은 보안 인증값이 아니다.

화면의 메뉴는 전투를 멈추지 않으며, 개인 결과를 보는 동안에도 방의 시뮬레이션은 계속된다. 새 출격은 같은 방에 요청한다. 렌더링에 사용하는 자기 편대 표시와 카메라는 복제 시뮬레이션의 기준 편대 표시를 변경하지 않는다. 서버 실행·Cloud 배포 절차는 [Colyseus 배포 안내](colyseus-deployment.md)에 정리했다. 로컬 검증과 실제 유료 서버의 성능·배포 검증은 별도다.

## 이번 변경의 검증 결과

- 전체 자동 테스트 384개 통과, 실패 0. 기존 369개와 방 시뮬레이션·운영 테스트 15개를 포함한다. 배포용 빌드도 성공했다.
- 실제 내부 AI를 18,000틱, 게임 시간 5분 동안 실행했다. 사람 0명에서 최소 5개 편대가 유지됐고, 시험 중 드론은 최대 507기였다. 이 측정은 서버 상품의 수용량 보장이 아니다.
- 살아 있는 5개 편대를 같은 틱에 모두 격추시켜도 게임이 계속되고 새로운 편대 5개가 보충됐다.
- 서로 다른 시드 40개에서 30명 입장과 퇴장 후 신규 10명 교체를 확인했다. 정원 초과·중복 입장도 검사했다.
- Node 24.21.0과 macOS JavaScriptCore에서 시드 1·23·99를 각각 1,200틱 계산했다. 입장·AI 전환·새 출격·중간 상태 복원을 포함한 33개 전체 상태 비교 지점이 일치했다. 이 실행 환경 비교에서는 생존을 고정하기 위해 기체에 무적 시간을 부여했고, 실제 격추·보충은 별도 시험했다.
- 두 실행 환경의 직렬화 결과는 1,715,526바이트로 같았으며 SHA-256은 `65baf8238ab836ab97eb7a05254708ac804d566b8017075ceba89b8e989602f5`였다. 이번 변경에서는 실제 브라우저 접속·네트워크 지연 시험을 실행하지 않았다.

## 검증 기준

- 시작 시 AI 5개, 사람 수 변화와 다중 격추 후에도 최소 5개.
- 접속이 끊긴 편대가 AI로 실제 이동하며 무적 시간이나 에너지를 초기화하지 않음.
- 같은 접속자의 재입장도 새 지휘기 ID와 드론 4개로 시작하며 이전 편대를 회수하지 않음.
- 두 명 이상의 서로 다른 입력이 각자의 편대에만 적용됨.
- 사망, 나가기, 빈 방에서도 서버 시뮬레이션이 계속됨.
- 정원·중복 접속·잘못된 입력을 처리하며 새 방을 만들지 않음.
- 같은 시드와 순서가 같은 입력·입퇴장으로 같은 결과를 재현하고 저장 후 이어 계산해도 일치함.
